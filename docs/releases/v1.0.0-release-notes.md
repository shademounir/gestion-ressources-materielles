# Release Notes v1.0.0

## Resume de la release

La release `v1.0.0` marque la stabilisation du socle backend et DevSecOps du projet Gestion des Ressources Materielles.

Elle couvre les premiers flux metier structurants :

- authentification et securite ;
- gestion des utilisateurs ;
- gestion des departements ;
- expression des besoins departementaux ;
- gestion des fournisseurs ;
- appels d'offres ;
- offres fournisseurs ;
- selection de l'offre gagnante.

Elle integre egalement une chaine CI/CD professionnelle avec controles qualite, securite et conservation des artefacts GitHub Actions.

## Perimetre fonctionnel

Fonctionnalites incluses :

- connexion utilisateur par JWT ;
- deconnexion stateless ;
- protection des endpoints par JWT et roles ;
- creation d'utilisateur par un administrateur ;
- attribution de role utilisateur ;
- desactivation logique d'utilisateur ;
- creation de departement ;
- rattachement d'un utilisateur a un departement ;
- declaration d'un besoin departemental avec lignes de besoin ;
- creation, historique et desactivation fournisseur ;
- creation d'un appel d'offres depuis un besoin ;
- publication d'un appel d'offres ;
- enregistrement d'une offre fournisseur ;
- selection de l'offre gagnante.

## Perimetre technique

Socle technique couvert :

- backend NestJS et TypeScript strict ;
- Prisma ORM avec PostgreSQL ;
- DTO validation ;
- Swagger/OpenAPI ;
- RBAC foundation ;
- tests unitaires Jest ;
- frontend React/Vite foundation ;
- CI GitHub Actions ;
- SonarCloud ;
- CodeQL ;
- Semgrep ;
- publication d'artefacts GitHub Actions.

Commandes locales de reference :

```powershell

npm run test
npm run build
```

Controles CI attendus :

- lint backend ;
- lint frontend ;
- typecheck backend ;
- typecheck frontend ;
- tests unitaires backend ;
- tests unitaires frontend ;
- coverage backend ;
- coverage frontend ;
- build backend ;
- build frontend ;
- analyse SonarCloud.

## Controles securite

Controles DevSecOps disponibles :

- authentification JWT ;
- RBAC sur endpoints sensibles ;
- validation DTO ;
- CodeQL pour analyse securite GitHub ;
- Semgrep pour patterns securite TypeScript/JavaScript ;
- SonarCloud pour security hotspots et maintenabilite ;
- exclusion des secrets dans les artefacts ;
- documentation des strategies security scanning.

## Artefacts disponibles

Artefacts GitHub Actions attendus :

- `backend-coverage` ;
- `frontend-coverage` ;
- `backend-build` ;
- `frontend-build` ;
- `semgrep-report`.

Les artefacts sont conserves 14 jours et servent de preuves CI/CD pour review, audit et soutenance.

## Limites connues

Limites fonctionnelles :

- pas encore de frontend metier complet ;
- pas encore de module inventaire complet ;
- pas encore de gestion des ressources materielles livrees ;
- pas encore de maintenance applicative complete ;
- pas encore de notification metier ;
- pas encore de refresh token complet ;
- pas encore de workflow complet de validation departementale.

Limites techniques :

- deploiement production non active ;
- JFrog Artifactory documente mais non integre ;
- Docker utilise comme socle local, sans publication registry ;
- security gates progressifs, pas encore tous bloquants ;
- pas encore de monitoring production.

## Risques acceptes

| Risque                               | Acceptation                                              |
| ------------------------------------ | -------------------------------------------------------- |
| Frontend metier incomplet            | Release centree backend et DevSecOps foundation          |
| Security scans progressifs           | Blocage renforce prevu dans les releases suivantes       |
| Pas de deploiement production        | Release documentaire et technique stable, non production |
| Couverture fonctionnelle partielle   | Roadmap continue story-by-story                          |
| Pas d'Artifact Repository enterprise | GitHub Actions Artifacts utilise en court terme          |

Priorites recommandees apres `v1.0.0` :

- developper le frontend metier ;
- finaliser inventaire et ressources materielles ;
- implementer affectations et maintenance ;
- introduire refresh token complet ;
- ajouter notifications ;
- renforcer quality gates ;
- preparer Docker registry ou JFrog Artifactory ;
